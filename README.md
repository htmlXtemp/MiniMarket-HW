# Мини-маркет

Учебный проект: витрина с UI-китом и переключаемой темой на styled-components.

## Запуск

```bash
npm install
npm run dev
```

После запуска откройте http://localhost:5173.

## Скрипты

- `npm run dev` - dev-сервер Vite
- `npm run build` - проверка типов и сборка в папку `dist`
- `npm run preview` - просмотр собранной версии
- `npm run typecheck` - только проверка типов

## Разделы на сайте

- "Тема" - светлая и тёмная темы, палитра и сохранение выбора.
- "UI-кит" - Button, Badge, Input, Card и Grid.
- "Каталог" - поиск, фильтр категорий, корзина и пустое состояние.
- "Тест" - 20 карточек, фильтры, теги, добавление и удаление товаров.

## Структура минимаркета

```text
src/
  pages/    собственно страницы вышеописанных разделов
  shared/   данные товаров(карточек) и форматирование цены
  theme/    типы темы, палитры, ThemeProvider и глобальные стили
  ui/       переиспользуемые компоненты
```

## styled-components против CSS Modules на моём проекте

В моём проекте styled-components лучше, потому что вся палитра лежит в одном объекте темы, а ThemeProvider передаёт её каждому компоненту через `props.theme`. При смене темы React просто подставляет другой объект и цвета пересчитываются без дублирования классов, и без ручного переключения CSS-переменных. CSS Modules, как в первом задании практики, хорошо изолируют классы, но тему всё равно пришлось бы описывать через CSS-переменные и атрибут `data-theme`. Варианты кнопок и размеры в styled-components удобно держать в объектах с `css` и выбирать по transient props вроде `$variant`, и эти служебные props не попадают в разметку. Наверное, для статичной витрины без смены темы CSS Modules были бы проще и быстрее, но для моего минимаркета с темами, вариантами и переиспользуемыми компонентами styled-components реально просто удобнее (да и по заданию просили).
